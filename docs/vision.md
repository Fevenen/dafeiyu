# 通用屏幕视觉

屏幕开关位于麦克风、举手按钮旁，完整窗口和悬浮桌宠模式都有。显示器图标灰色表示关闭，绿色表示开启。

每次启动默认关闭，不会恢复上次的屏幕授权。关闭时停止屏幕轨道、清除内存预览，并在发送前剔除关闭或切换目标前取得的旧截图。已经发送到模型的画面无法撤回；历史文字描述可能仍留在对话中。

## 使用

1. 点击显示器图标开启；再次点击立即关闭，开启过程中也可取消。
2. 在旁边的设置中选择显示器或窗口。切换目标会关闭采集，需再次点击开启。
3. 点击刷新预览，确认观察对象。预览显示的是最近一次采集，不是持续发送的视频。
4. 在预览上拖动框选局部，再刷新或提问。绿色框内区域先从源图裁剪，再按长边限制等比缩放。恢复全图可撤销框选。
5. 开启期间，文字、麦克风一句话结束、主动聊天触发时会取得新画面。描述当前画面按钮可直接发起视觉提问；无有效截图时不会提交该提问。

支持 PNG/JPEG 和 1280/1600/1920/2560 长边预算，默认 PNG、1600。截图附带来源、时间、唯一编号、原尺寸、输出尺寸、局部范围和采集耗时。模型收到对应当前图片的来源与时间说明，提示旧描述可能过时、看不清时应明确说明。

预览和截图只保存在当前客户端内存中，不写入本项目的对话记录；模型请求诊断日志省略图片数据。模型服务自身的缓存和存储由其配置决定。

这是屏幕控制，独立于原有摄像头控制，不会打开摄像头。

## 在 DSH 工作区看屏幕

DSH 模型连接须指向桌宠网关 `http://127.0.0.1:18080/v1`。开启桌宠显示器按钮后，在 DSH 问“你看看我这个题目是干啥的”“看看屏幕上的报错”等当前画面问题，网关会向在线桌宠请求一张新截图，再随本轮问题转发给本地模型。普通闲聊、标题生成、工具结果后续轮次不请求截图；已有上传图片也不会额外混入屏幕。

屏幕已纳入QQ、提醒共用的能力路由。明确看屏幕的句子直接使用规则，其余用户消息统一进行一次受限意图分析，包括“这个怎么弄”“第二问呢”等含糊指代和普通闲聊。参考最近最多6条文字（每条最多600字），不把截图数据交给分类器。对象已在文字中说明时选择聊天；缺少当前视觉信息时选择observe_screen。该选择只表示需要请求图片，开启权限仍由桌宠开关控制，也不能确认消息发送。请求metadata.pet_client_uid可显式绑定一个已授权桌宠；未绑定且多个桌宠同时开启时拒绝猜测。

这仍使用同一个屏幕开关和选定区域：关闭、切换来源或断线会撤销授权并丢弃未完成截图；多个桌宠同时授权时不会猜测用哪一个。取图超时有上限，失败会向模型明确说明本轮没有画面。只读 DSH watcher 继续只负责播报文字，不自行截图。

`/api/vision/status` 可查看开关是否已与后台同步；默认 enabled=false。`/api/vision/snapshot` 只能向已授权客户端请求新帧，不具备打开屏幕的能力。

## 安装与构建

后端先按 README 安装。屏幕按钮需要重建桌面客户端；只有后端更新不会改变已有 exe：

```powershell
# 先关闭旧桌宠客户端，保留模型服务。
powershell -ExecutionPolicy Bypass -File .\scripts\build-client.ps1 -PetRoot "D:\我的助手\pet"
# 便携 Node 可另传 -NodeDir "D:\工具\node"
```

没有客户端源码时，脚本下载官方 Open-LLM-VTuber-Web 并固定在提交 `d176e7df2366952e3bacbf12cf9a8b18a4315932`，初始化子模块，然后应用本仓库 frontend 覆盖文件。已有源码要求版本 1.2.1；覆盖前备份到本机 bridge/data/backups。原上游许可保存在 frontend/LICENSE.upstream。

`-ApplyOnly` 可离线只应用源码，供已有构建流程或安装验证使用。代码、配置不依赖作者电脑路径。前端源码同步清单在 scripts/sync_sources.py；生成截图、模型、日志、node_modules 与打包产物不属于发布源。

## 验证与性能

- Node.js 24 LTS：在客户端源码目录执行 `node --test scripts/test-screen-vision.mjs`。
- 先执行 `node scripts/build-vision-fixture.mjs`，再用 Electron 运行 scripts/test-screen-ui.cjs，可用合成画面验证真实 Canvas 截图、裁剪和关闭竞态，不读取真实桌面。
- 本机合成图端到端测试识别出 `4826`；一次 1600×900、1024 视觉 token、CPU 视觉处理请求约 20 秒，仅为本机样本，不是性能保证。采集耗时与模型视觉耗时不同。
- 当前前端完整类型检查仍有上游 Live2D SDK 等历史错误；本次改动文件无类型错误，生产编译通过。没有通过关闭类型检查规则来隐藏上游问题。

目前提供用户控制的按次截图，不运行后台视觉推理，不新增软件专用适配。OCR、自动补看、多帧视觉记忆可在基线验证后独立增加。
