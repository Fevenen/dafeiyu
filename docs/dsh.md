# 在 DSH 里使用桌宠

## 配置步骤

1. 运行 install.ps1，找到安装目录中的 `bridge/data/generated/cordis.patch.ready.yml`。
2. 将片段合并到用户目录下 `.dsh/profiles/desktop/cordis.patch.yml`，保留原配置备份。
3. 在 DSH 打开安装器创建的 pet_workspace，新建会话，选择“大肥鱼（桌宠）”预设。工作区 AGENTS.md 提供人格，MCP 提供工具。
4. 使用本地 KVMem 时，把对应 provider 的 baseURL 设置为 `http://127.0.0.1:18080/v1`，实际上游通过 KVMEM_UPSTREAM 配置。
5. 运行桌宠启动器，确认后端、网关与 watcher 日志正常。

不要把生成片段中的本机路径提交到 GitHub。移动目录后重新安装，生成新片段并替换宿主旧配置。

## 命令处理

网关优先处理明确命令、联系人选择、确认和取消。其余用户消息全部进入一次语义分类，包括普通闲聊，不再先用关键词、固定句首或500字门槛排除。模型只看到精简能力目录、当前原文和最近最多6条文字（每条最多600字），不读取截图或工具输出。它可选择聊天、一个桌宠动作或澄清；只有明确的动作才进入对应工具，缺参数先追问。

分类为聊天后再流式调用回答模型。默认不给回答模型重复提供桌宠操作工具；明确的原生工作请求与工具后续轮次保留DSH原生工具。native_tools_policy=all 保留旧版按词筛工具行为，不建议用于默认桌宠会话。工具结果后续轮次、标题/摘要后台任务不重新路由用户旧命令。

分类失败或结果非法会直接提示未执行，不交给自由聊天编造结果。意图模型没有确认/取消发送的权限；这些仍只匹配用户本轮确认词。处理过的请求重试先返回已有结果，不重新分类或执行。

普通闲聊会比原来的直连回答多一次分类请求。本地六组样本的分类耗时约2.3至3秒，实际延迟以模型和上下文为准。桌宠文字入口与MCP的route_command也共用该分类器；这两个入口的截图仍由客户端既有流程管理，不由意图分类开启。

MCP 推荐调用 route_command(text=用户原文, request_id=本轮稳定ID)。直接调用 confirm_send 时必须提供 confirmation=用户本轮原始确认文字，例如“确认”；不能根据自己的判断编一个确认。

不要在每次闲聊前调用 recent_actions。它只用于查询发送状态，历史结果不能替代新请求。

“不用啦，你帮我喊小z起床”“上QQ喊他”会接入消息准备流程；后者只从最近一条用户命令中补齐对象和内容，不相信模型自述的发送结果。联系人不唯一时保存带账号标识的候选，回复“第一个”或完整名字后只准备消息，仍须下一轮明确确认才发送。候选按会话隔离，默认5分钟过期，取消或新消息准备会清理旧选择。

“等下帮我叫小z起床”会先询问多久后，并说明支持定时提醒用户去喊；这不代表支持给好友自动定时发送QQ。也可回复“现在”改为准备即时QQ消息。

网关每次请求都会附加当前简短回复和能力真实性规则，旧会话也生效；普通闲聊默认1至2句，明确要求详细、完整步骤或代码时允许展开。不会用截断返回文字来实现简短。

## 多会话

自定义宿主应传 X-Session-ID 和 X-Request-ID，或 metadata 对应字段。没有稳定会话 ID 的 DSH 接入，使用首条用户消息指纹并检查历史连续性；遇到同开场的分支冲突会停止动作。

需要同时独立操控多个 DSH 会话时，为各会话配置独立网关实例、端口和 BRIDGE_SESSION_ID（可通过不同 PET_CONFIG 文件），或扩展宿主让它传入稳定 ID。不要把所有会话强行绑定到同一固定 ID。

MCP stdio 进程默认各自隔离。重启 MCP 后请重新准备消息再确认，不复用旧的 pending。

## 语音

watcher 每0.3秒检查DSH会话，读取 `~/.dsh/sessions` 中的 v4 完整压缩日志，在本轮完成后分句提交全文，包括没有句末标点的最后一段。`session_projcache` 的 `turnOutline.response` 只是约120字的摘要，仅用于发现会话，不再作为播报正文。它只负责播报，不执行发消息或提醒。

依赖 `zstandard`（已包含在 requirements.txt）。默认全文目录可用 `DSH_HISTORY`、配置项 `dsh_history` 或 `--history` 覆盖；没有可读全文时不会拿摘要冒充完整回复。升级时跳过旧监听器已经播过的当前回复，避免突然重播长篇旧内容。

```powershell
python -m bridge.dsh_watch --dir "<你的工作区>"
python -m bridge.dsh_watch --list
python -m bridge.dsh_watch --session <会话ID> --dry
```

--dry 只打印，不连接模型、QQ 或桌宠接口，也不修改播放游标。入队失败不会推进游标；入队后的实际播放状态通过 /api/speech/status 查询。

升级后必须停止旧版监听器再启动新版；旧版仍有执行命令的逻辑，不能与新版并行运行。
